# Hunterилка · графовый антифрод

### Программная система выявления аномальных транзакций в динамическом графе финансовых операций

**От отдельного перевода к связанному случаю для расследования.**

Hunterилка анализирует финансовые операции в двух масштабах: оценивает новую транзакцию по доступной истории и ищет подозрительные сочетания переводов в динамическом графе. Специалист получает сохранённый случай с конкретными операциями, связями, основаниями сигнала и объяснением модели.

Предметная область v1: AML, выявление потенциальных схем отмывания средств. Система поддерживает анализ и приоритизацию рассмотрения; итоговое решение принимает специалист.

**Python 3.12 · CatBoost · Isolation Forest · NetworkX · Streamlit**

[Архитектура](docs/architecture.md) · [Запуск](RUN_GUIDE.md) · [Эксперимент](docs/results.md) · [Данные](docs/data_card.md) · [Требования и проверки](docs/traceability.md)

## Почему два уровня

Один перевод может выглядеть обычным, но стать значимым в цепочке, кольце или распределении средств. Высокая оценка отдельной операции также требует понятного контекста. Поэтому единицей работы специалиста становится **случай**, а не строка с числом.

| Уровень | Вопрос | Механизм | Результат |
|---|---|---|---|
| Операция | Насколько подозрительна новая транзакция с учётом прошлого? | CatBoost: поля операции, история счетов, связи и топология | Оценка операции и SHAP по сохранённому вектору |
| Структура | Насколько необычно сочетание связанных переводов? | Независимый поиск кандидатов, затем Isolation Forest по их признакам | Оценка структуры, её состав и диагностические признаки |
| Рассмотрение | Какие факты проверять и какое решение зафиксировать? | Сохранённый граф случая, очередь, статусы и экспорт | Воспроизводимое основание рассмотрения |

**Структурный поиск не отсекается порогом CatBoost.** Он может сформировать случай из операций с невысокими индивидуальными оценками. Две оценки относятся к разным объектам и сохраняются раздельно.

**Две очереди рассмотрения:** операции упорядочены по оценке CatBoost, структуры по необычности. Структурная аномалия не вытесняет сильную отдельную операцию. Основания обеих моделей видны в карточке.

## Схема 1. Архитектура системы

![Схема 1. Архитектура Hunterилка: временной граф, два уровня анализа и рабочее место специалиста](docs/assets/architecture.svg)

**Временной контракт:** вся группа операций времени `t` сначала оценивается по состоянию `S(t−)`. Затем группа целиком добавляется в граф и запускается поиск структур. Перестановка строк внутри одного времени не создаёт искусственной истории.

Обучение отделено от применения: подготовка событий, построение признаков, обучение и оценка выполняются через `scripts/`. Воспроизведение использует тот же вычислительный порядок в `src/pipeline.py`. Метки хранятся отдельно и доступны обучению и оценке, но не рабочему поиску кандидатов.

## Инженерные решения

| Решение | Зачем оно нужно | Реализация |
|---|---|---|
| Три представления графа | Сохранить точные события и обеспечить быстрые запросы и читаемый экран | Переводы как события; агрегированные связи пар; компактный снимок случая |
| Скользящая история | Контролировать актуальность контекста | Горизонт графа 30 дней, независимые агрегаты 1 ч и 24 ч |
| Ограниченный поиск | Ограничить вычислительную работу на временную группу | Отдельный лимит обхода для каждой новой операции и счёта; предел числа кандидатов и диагностика неполноты |
| Снимок и версии случая | Сохранить основание после изменения или истечения рабочего графа | JSON деталей, Parquet-индекс, версии и комментарии |
| Контракт модели | Исключить незаметное применение модели к другим признакам | Проверка конфигурации, порядка признаков и контрольных сумм |
| Раздельные вычисления и интерфейс | Проверять алгоритмы независимо от экрана | Ядро без Streamlit; UI вызывает готовые функции и сервис случаев |

В реализации используется **модульное Python-приложение с файловым хранением**. Состояние инкапсулировано в `RollingGraph`, `ReplayController` и `CaseService`; признаки, обучение и метрики выражены обычными функциями. Это сохраняет явные границы ответственности без дополнительных сетевых сервисов и иерархий классов.

Для ТРПС зафиксированы декомпозиция, контракты компонентов, итерационно-инкрементальный жизненный цикл и связь требований с испытаниями: [архитектурные решения](docs/architecture.md), [матрица требований](docs/traceability.md).

## Рабочее место специалиста

- Отдельные очереди операций и структур с фильтрами по типу, дате и статусу.
- Выбор периода: число всех операций, пороговые сигналы CatBoost, динамика по дням и найденные формы.
- Счётчики новых, требующих проверки и рассмотренных карточек; решение сохраняется между открытиями.
- Направленный граф выбранного случая: основание сигнала и дополнительный контекст.
- Отдельное ребро для каждого перевода, серое окружение и красная схема; нажатие раскрывает сумму, время и участников.
- Обзор сети с поиском счёта и раскрытием его участка за выбранный период.
- Таблица исходных операций, две отдельные оценки и объяснение выбранной транзакции.
- Статус, комментарий, экспорт JSON и CSV.
- Пошаговое воспроизведение, пауза и восстановление из контрольной точки.

В браузер передаётся граф выбранного случая: по умолчанию до 40 счетов и 80 связей, с расширением до 100 и 200. Полный активный граф остаётся в вычислительном контуре. Поиск поддерживает цепочки, кольца, взаимные пары, сбор, распределение и составные структуры.

Обзорные счётчики охватывают весь выбранный период; карта показывает ограниченный участок, а не уменьшенную копию миллионов рёбер. Сохранённое окружение случая не содержит будущих переводов. Примеры поддерживаемых форм выделены как примеры, даже когда оценки моделей ниже порогов. Без полного CSV доступны готовые карточки и сохранённые участки сети; подготовленные данные открывают поиск произвольного счёта.

## Эксперимент и результаты

Основной запуск использует весь банковский период IBM HI-Small, почти 18 дней. Ранние данные служат обучению, следующие выбору модели и порогов, последние итоговой проверке. Сравниваются A с признаками операции и истории счетов и B с дополнительными графовыми признаками; обе с весами классов и без них.

На отложенном по времени test **B_plain находит 100 положительных операций в первых 100 и 492 в первых 500** по оценке модели. AP **0.7209**, ROC AUC **0.9906**. При случайном выборе 500 операций ожидалось бы около 0.90 положительных.

При зафиксированном на validation пороге: **270 находок и 4 ложных сигналов**. Отбор первых 500 и пороговые сигналы показаны отдельно. Второй уровень добавил 28 положительных операций к пороговым сигналам первого; качество структурного отбора слабее, поэтому у него отдельная очередь.

Расчёт: **4,930,063 операций, 17.68 дня**. Полный исходный период; синтетический IBM HI-Small. [Четыре модели, ограничения и проверка очередей](docs/results.md).

Отчёт показывает каждый этап отдельно: сколько положительных операций вошло в найденные структуры, сколько прошло отбор второй модели, что добавилось сверх первого уровня и что изменилось при одинаковом числе карточек. Положительная операция внутри случая является приближённой оценкой, а не разметкой полной схемы отмывания.

## Запуск на Linux

Python 3.12. Поддерживается обучение CatBoost на NVIDIA GPU; граф и Isolation Forest выполняются на CPU. PyTorch не требуется. Команды выполняются из папки с `app.py`.

Для просмотра сохранённых моделей и случаев:

```bash
python3.12 -m venv ../.venv
source ../.venv/bin/activate
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

Откройте [localhost:8501](http://localhost:8501). В поставке указано, к какому профилю относятся карточки. Для полного повторного обучения:

```bash
python -m scripts.check_environment --device GPU
python -m scripts.download_data
python -m scripts.run_pipeline --device GPU
```

Если CSV уже скачан, команду загрузки пропустите и передайте `--input /путь/HI-Small_Trans.csv` в `run_pipeline`. Для CPU используйте `--device CPU`. После обучения перезапустите приложение.

[Пошаговая инструкция](RUN_GUIDE.md) содержит результаты каждого этапа, повторный запуск после ошибки и сборку папки для GitHub.

## Проверки

```bash
python -m unittest discover -s tests -v
```

Проверки охватывают время, окна, повторные переводы, валюты, независимость от меток, формы структур, разбиение по времени, охват операции после первых 128 строк, независимость двух очередей и сохранение случаев. Дополнительно проверяется сквозное обновление карточек и открытие интерфейса.

## Область применения v1

Система предназначена для исследования AML-сценариев и локального рассмотрения случаев. Весь HI-Small содержит почти 18 дней, поэтому даже полный запуск не обеспечивает 30 дней начальной истории. Удаление событий за пределами окна проверяется отдельными тестами.

Поиск начинает обход от каждой новой операции, но глубина, число просмотренных связей и число сохранённых кандидатов ограничены. Полнота обнаружения всех схем не заявляется. Предел 6 млн активных событий рассчитан на рабочую станцию с большим объёмом RAM; он не является измеренным пределом производительности. Многопользовательское хранение и работа на банковских данных не проверены.

Происхождение данных и условия использования: [NOTICE.md](NOTICE.md), [описание данных](docs/data_card.md).
