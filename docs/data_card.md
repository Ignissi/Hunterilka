# Данные

Источник: синтетический набор IBM Transactions for Anti Money Laundering, вариант HI-Small.
[Страница набора на Kaggle](https://www.kaggle.com/datasets/ealtman2019/ibm-transactions-for-anti-money-laundering-aml). Лицензия: CDLA-Sharing-1.0. Проект не создаёт обучающие строки.

Исходный CSV содержит ~5.08 млн строк с 1 по 18 сентября 2022 года. При импорте исключаются криптовалютные операции и некорректные строки (с причинами в `data/rejected.csv`); остаётся ~4.93 млн банковских операций, из них ~5.1 тыс. с меткой отмывания (~0.1%).

Правила импорта (`src/data.py`):

- Счёт определяется парой банк/номер (`021:800737690`): номер уникален только внутри банка. Ведущие нули сохраняются.
- `transaction_id` — номер исходной строки CSV: устойчив между запусками.
- Суммы сохраняются исходными десятичными строками; агрегаты считаются раздельно по валютам, валюты не складываются.
- Метки `is_laundering` отделяются в `labels.parquet` и доступны только обучению и оценке.
- Повторные одинаковые строки не удаляются: это разные операции.

Разделение по времени: 60/20/20 по числу операций (train / validation / test), границы только по времени, без меток; все операции одной минуты попадают в одну часть. Каждая часть обязана содержать не менее 10% операций и оба класса, иначе подготовка останавливается.

Особенность экспериментального набора: после 10 сентября резко падает число операций. Поэтому `scripts/evaluate.py` показывает весь test и два периода отдельно, с размерами и количеством положительных меток. Смена распределения сама по себе не доказывает утечку; различие качества устанавливается расчётом. Граница 11 сентября относится к исследуемому HI-Small, а не к произвольному банковскому источнику.

`data/manifest.json` фиксирует фактические объёмы, границы сплита, число исключённых строк и период истории.
