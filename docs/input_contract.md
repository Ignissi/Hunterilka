# Контракт входящих операций

## Файловый вход

`run_inbox` читает каталог поступления. Один файл содержит все операции одной завершённой минуты. Источник сначала пишет файл с расширением `.tmp`, затем атомарно переименовывает его в `YYYYMMDDTHHMMSS.json`. Сервис читает только `.json`.

Файлы публикуются по возрастанию времени. Следующая минута публикуется после завершения предыдущей. Дополнение ранее опубликованной минуты и доставка опоздавших операций в этой версии не поддерживаются: обработка останавливается с объяснением. Пустые минуты можно пропускать.

Пример `20261021T120700.json`:

```json
{
  "events": [{
    "transaction_id": 9000001,
    "timestamp": "2026-10-21T12:07:00",
    "source_bank": "01",
    "source_account": "A001",
    "target_bank": "02",
    "target_account": "B002",
    "amount_paid": "15000.00",
    "payment_currency": "USD",
    "amount_received": "15000.00",
    "receiving_currency": "USD",
    "payment_format": "Wire"
  }]
}
```

`transaction_id` — устойчивый уникальный идентификатор перевода, целое число от 0 до 2^63−1. Повторная доставка сохраняет исходный идентификатор. Идентификаторы не переиспользуются источником. Время приводится к UTC с минутной гранулярностью; строка без часового пояса трактуется как UTC. Время файла должно совпадать со временем всех его операций.

Суммы передаются неотрицательными десятичными строками, валюты и категории — строками в согласованном справочнике. Сочетание банка и номера определяет счёт. Двоеточие в этих двух полях зарезервировано. Метки `is_laundering`, `split` и вычисленные признаки не принимаются.

После успешного сохранения в PostgreSQL файл переносится в подкаталог `processed`. При ошибке он остаётся на месте. Если БД уже сохранила последнюю минуту, а перенос файла был прерван, повтор проверяет содержимое и не создаёт новые операции или случаи. Обработанные файлы могут содержать конфиденциальные сведения: срок хранения и доступ задаются при развёртывании.

Максимальный размер файла — 64 MiB. В памяти находится одна входная минута и рабочее окно графа. Размер окна и плотность связей определяют потребление памяти. Источник передаёт операции в согласованном формате; адаптер конкретной банковской системы реализуется на её стороне или отдельным интеграционным компонентом.

## История перед запуском

`--score-from` задаёт начало оценки. Файлы раньше этого времени загружают доступную историю без создания сигналов. Это помогает рассчитывать признаки первых рабочих операций. Все исторические файлы должны быть опубликованы до первой оцениваемой минуты. При отсутствии истории сервис начинает с пустого графа.

## Отдельный режим воспроизведения IBM

`run_stream` читает `events.parquet` и проверяет его принадлежность эксперименту. Это средство повторения демонстрации. `run_inbox` не читает `data/manifest.json`, не использует обучающие метки и не требует совпадения нового источника с IBM.
