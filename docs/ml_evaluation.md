# Обучение и оценка моделей

## Задача

CatBoost ранжирует новые переводы по признакам операции, прошлой активности счетов и их связей. Isolation Forest отдельно оценивает найденные структуры. Разметка используется при обучении CatBoost и измерении качества, но не поступает в рабочую БД или новый источник.

## Разделение истории

Для одного воспроизводимого эксперимента операции сортируются по времени. Примерно 60% ранних операций используются для обучения, следующие 20% — для выбора варианта и порогов, последние 20% — для оценки результата. Одна временная группа не делится между частями.

Большая первая часть даёт модели материал для обучения; две последующие части отделяют выбор решения от его проверки. Пропорция 60/20/20 — заранее заданная конфигурация эксперимента, а не доказанный оптимум или правило эксплуатации. Границы рассчитываются по количеству и времени операций без использования меток и качества моделей. Этот эксперимент не сравнивал разные пропорции.

Для новых данных в работе разбиения нет: каждая законченная минута поступает в сервис анализа. Порядок «прошлое → будущее» нужен при проверке, чтобы воспроизвести отсутствие будущих событий в момент расчёта признаков.

## Выбор модели

Сравниваются A (операция и история счетов) и B (дополнительно графовые признаки); каждый вариант обучается без весов и с весами классов. На validation выбирается вариант с наибольшим числом положительных среди первых 100, при равенстве — с наибольшим AP. Порог выбирается по бюджету рассмотрения на validation и затем сохраняется.

Test оценивает выбранное решение. Для v1 и v2 использован один контрольный период; сравнение версий не является независимой проверкой на новых данных. Полноценная оценка переноса на другой банк требует его истории и разметки.

## Защита от использования будущего

Признаки всех переводов одной минуты рассчитываются по графу до этой минуты. Затем вся группа добавляется в граф. Признаки `history_age` и `history_warmup`, зависевшие от выбранного начала загруженной истории, исключены в v2. Остальные признаки истории счетов сохранены.

Версия признаков, их настройки, seed, контрольные суммы данных и файлов моделей записываются при обучении. Рабочий сервис проверяет совместимость загруженной модели с вычисляемыми признаками. SHAP использует сохранённый вектор той модели, которая создала оценку.

## Метрики

Precision@K — доля положительных среди K первых операций по оценке модели. Recall@K — доля всех положительных операций, попавших в эту группу. AP и ROC AUC описывают ранжирование при рассмотрении разных границ отбора. Сигналы при рабочем пороге считаются отдельно от top-K.

Основная таблица отчёта относится ко всему test. Дополнительные временные срезы показывают, как качество меняется внутри него. Граница диагностического среза IBM используется только при составлении отчёта; сервис приёма и модели не отбирают рабочие операции по этой дате.

## Что сохранено после локального расчёта

| Файл | Назначение |
|---|---|
| `artifacts/A_plain.cbm`, `A_balanced.cbm`, `B_plain.cbm`, `B_balanced.cbm` | Четыре обученные модели для сравнения |
| `artifacts/isolation_forest.joblib` | Обученная модель структур |
| `artifacts/model_meta.json` | Выбранная модель, признаки, пороги и идентификаторы |
| `reports/metrics.json`, `reports/experiments.csv` | Числа эксперимента |
| `docs/results.md`, `docs/version_comparison.md` | Читаемый отчёт и сравнение версий |

Рабочий сервис загружает выбранный CatBoost и Isolation Forest. Для применения моделей не требуется повторять обучение. `package_release` включает обученные файлы в отдельный комплект поставки.
