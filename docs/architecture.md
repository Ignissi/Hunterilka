# Архитектура Hunterилка v1.1

Программная система выявления аномальных транзакций в динамическом графе финансовых операций.

![Схема 1. Архитектура](assets/architecture.svg)

## Компоненты и ответственность

| Компонент | Вход | Ответственность | Выход |
|---|---|---|---|
| data | Исходный IBM CSV | Проверка, фильтр, сортировка, устойчивые ID | События, отдельные метки, паспорт |
| graph | Полные временные группы | Истечение и согласованное обновление событий, связей и окон | Состояние истории |
| features | Новая операция и прошлое | Одна строка признаков без будущих событий | Вход CatBoost |
| patterns | Новые операции и обновлённый граф | Поиск поддерживаемых форм с ограничениями | Конкретные группы переводов и их признаки |
| pipeline | Состояние, группа, модели | Единый порядок подготовки и применения | Признаки, две оценки, диагностика |
| replay | Подготовленные события | Позиция, шаг, пауза, контрольная точка | Управляемый ход обработки |
| cases | Сигналы и операции | Снимки, версии и рассмотрение | JSON деталей и индекс Parquet |
| review_queue | Индекс карточек и выбранная очередь | Сортировка операций по CatBoost, структур по необычности | Отдельные списки без конкуренции разных оценок |
| snapshot | События и время обнаружения | Ограниченное окружение без будущих и истёкших событий | Сохранённый срез для отображения |
| workspace | Дневные сводки, индекс и снимки | Выбор периода, формы и статуса; обзор сети | Управляемое рассмотрение |
| app, visualization | Сохранённый случай | Ограниченный граф, объяснение, решение | Рабочее место и экспорт |
| scripts/train, evaluate | Подготовленные таблицы | Обучение отдельно от применения, оценка после прогнозов | Модели и измеренные результаты |

## Время

Порядок каждой группы: истечение → признаки из прошлого → CatBoost → добавление целой группы → поиск структур → Isolation Forest → случай. Строки одного времени видят одно прошлое. Метки не подключены к графу и поиску. Обучение и воспроизведение используют одну функцию `process_group`.

Активная история хранит события за последние 30 дней. Агрегаты за час и сутки истекают отдельно. Нехватка начальной истории отражается в признаках; длительность фактически загруженного профиля показана в паспорте и интерфейсе. Полный HI-Small охватывает почти 18 дней.

## Поиск и стоимость

В v1.1 обход начинается от каждой новой операции и каждого затронутого счёта. Лимиты применяются к отдельному обходу: пути 128 просмотренных записей, звёзды 256, составные структуры 128. Число путей и размер соседства также ограничены. Поэтому стоимость растёт с размером входной группы; фиксированного общего лимита 5000 на всю группу больше нет.

До 3000 уникальных кандидатов сохраняются на группу. При переполнении выбираются кандидаты с меньшим устойчивым хешем ID. Это воспроизводимый отбор без меток и оценок моделей, независимый от порядка обхода. Диагностика сообщает ограниченные обходы и отброшенные кандидаты. Полный охват всех форм не гарантируется.

В памяти находятся активный граф и входные события. Признаки записываются порциями в Parquet, а кандидаты последовательно в JSONL. Файловое хранение и однопроцессный граф выбраны для локального выпуска. Полный профиль рассчитан на станцию с большим объёмом RAM.

## Объекты с состоянием

Операции и структуры имеют отдельные очереди. Сложение оценок не применяется: одна оценка относится к переводу, другая к группе переводов. В сохранённом test доступны первые 500 операций по CatBoost, включая явно обозначенные оценки ниже рабочего порога. Воспроизведение по-прежнему сохраняет сработавшие сигналы по зафиксированным порогам.

`scripts.refresh_review` обновляет карточки и отчёт после готового расчёта. Он повторяет прогноз на сохранённых признаках и проверяет совпадение с отчётом; модели, признаки и структурный поиск не меняются. Решения специалиста находятся отдельно в `runs/demo_review`; новый набор карточек получает собственную папку рассмотрения.

`scripts.build_workspace` готовит отображение: сводки всей истории по дням, количество версий кандидатов и уникальных эпизодов каждого семейства, пороговые сигналы CatBoost и ограниченные окружения карточек. Дополнительные примеры форм выбираются без меток и явно отмечаются. Расчётные модули и параметры моделей не меняются.

Окружение для экрана восстанавливается по временному индексу событий на момент обнаружения. Это визуальное представление доступной истории, а не повторный расчёт входа модели; SHAP использует исходный сохранённый вектор. На графе различаются отдельные переводы одной пары, основание и контекст. Статистические сводки охватывают весь период, а обзор сети раскрывает ограниченные участки. Статусы рассмотрения переносятся между версиями оформления по ID случая.

`RollingGraph` сохраняет согласованность событий, индексов пар и агрегированных связей. `ReplayController` продвигается только по целым временным группам. `CaseService` отделяет основание случая от меняющегося графа и сохраняет комментарии при обновлении версии.

Контрольная точка содержит позицию, версии данных, настроек и модели. Восстановление пересчитывает историю до завершённой группы. Файлы записываются через временный файл и замену; общей ACID-транзакции между файлами и памятью нет.

## Технология разработки программных систем

| Решение | Выбор и основание |
|---|---|
| Жизненный цикл | Итерационно-инкрементальный: завершение сквозного сценария, проверки, измерение и исправление |
| Декомпозиция | Отдельные ответственности данных, состояния, вычислений, хранения и интерфейса |
| Парадигма | Классы для состояния; прямые функции для ML, признаков и метрик |
| Архитектура | Модульное приложение с файловым хранением |
| Интеграция | От проверенных частей к полному пути и проверке интерфейса |

Ограничения выпуска: локальное рассмотрение, нет отдельного фонового сервиса, сетевого API и многопользовательской БД. Полнота истинных схем IBM не оценивается без соответствующей разметки схем.
