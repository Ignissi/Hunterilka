# Hunterилка v1.1: Linux и NVIDIA GPU

Все команды выполняются из папки с `app.py`. Полный расчёт создаёт новые данные, модели и отчёты. Используйте отдельную распакованную папку v1.1; старую версию не перезаписывайте.

## Если полный расчёт уже завершён

Для нового рабочего места с окружением, периодами и каталогом схем после установки исправления:

```bash
source ../.venv/bin/activate
python -m unittest discover -s tests -q
python -m scripts.build_workspace
python -m streamlit run app.py
```

`build_workspace` читает готовые события и каталог кандидатов, повторно применяет сохранённую модель, строит дневные сводки и окружение карточек. Обучение и вычисление ML-признаков не выполняются. На полном наборе чтение каталога занимает время; команда печатает этапы и прогресс. Повторный `run_pipeline` для этого исправления не нужен.

На экране выберите период, очередь и форму переводов. Карточка выбирается широкой строкой над графом, кнопками «Назад» / «Далее» или строкой раскрытого списка. Красным показано основание выбранного случая, серым его историческое окружение. Нажатие на ребро раскрывает отдельный перевод. Переключатель «Расширенный срез» доступен только при наличии дополнительных сохранённых связей.

В «Обзоре сети» можно искать счёт и раскрывать его участок за выбранный период. С полными подготовленными данными доступны произвольные счета; в публикации без CSV доступны сохранённые участки. Счётчики периода относятся ко всей истории, рисунок всегда имеет явные пределы. Статусы и комментарии прежних рассмотрений переносятся по ID случая при обновлении оформления.

После сохранения решения карточка сразу меняет статус и пересчитываются счётчики новых и рассмотренных. Примеры форм, добавленные для изучения топологии, отмечены отдельно и не выдаются за подтверждённое мошенничество.

### Только обновление очередей предыдущей версии

Для обновления очередей после установки исправления достаточно:

```bash
source ../.venv/bin/activate
python -m unittest discover -s tests -v
python -m scripts.refresh_review
python -m streamlit run app.py
```

Команда `refresh_review` повторно применяет готовую основную модель к готовым признакам test, проверяет совпадение результатов и сохраняет первые 500 операций. Структурные примеры остаются в отдельной очереди. Обучение и поиск по графу не выполняются. В полном запуске от 20 октября получено 100 положительных среди первых 100 и 492 среди первых 500; команда должна воспроизвести эти числа.

Обновляются `demo/`, `reports/metrics.json`, `docs/results.md` и блок результатов README. Модели, признаки, конфигурация и комментарии в `runs/` не меняются. Новый набор карточек открывается отдельно от прежних рассмотрений. Для повторного запуска Streamlit остановите старый сервер через `Ctrl+C` в его терминале.

## 1. Среда

Окружение располагается рядом с папкой проекта, на уровень выше. Если `../.venv` уже есть, достаточно активировать его; создавать заново не нужно.

```bash
python3.12 --version
python3.12 -m venv ../.venv
source ../.venv/bin/activate
python -m pip install -r requirements.txt
python -m pip check
python -m unittest discover -s tests -v
```

Если `python3 --version` уже показывает 3.12, замените `python3.12` на `python3`. Ожидается `OK` у тестов; `pip check` сообщает `No broken requirements found.` Если окружение уже создано во внешней папке, повторное создание не нужно: выполните `source ../.venv/bin/activate` и используйте `python` в командах ниже.

## 2. Проверка видеокарты до большого расчёта

```bash
python -m scripts.check_environment --device GPU
```

Команда выводит название GPU, память и версию драйвера, затем выполняет маленькое обучение CatBoost. Ожидается `Проверка обучения пройдена: GPU`. Если проверка завершилась ошибкой, полный расчёт не запускайте; сохраните сообщение. Команда не меняет модели проекта. GPU используется непосредственно CatBoost, без PyTorch.

## 3. Исходный CSV

Если файл уже есть, используйте его полный путь в следующем шаге. Иначе:

```bash
python -m scripts.download_data
```

Ожидается `data/raw/HI-Small_Trans.csv`, примерно 476 МБ. При недоступности загрузки скачайте HI-Small_Trans.csv со [страницы IBM AML](https://www.kaggle.com/datasets/ealtman2019/ibm-transactions-for-anti-money-laundering-aml). Не пересохраняйте файл через Excel.

## 4. Полный расчёт

```bash
python -m scripts.run_pipeline --device GPU
```

Если файл находится в другой папке:

```bash
python -m scripts.run_pipeline --device GPU --input /полный/путь/HI-Small_Trans.csv
```

По умолчанию обрабатывается весь файл. Не добавляйте `--limit 500000`: это снова ограничит период. Граница 30 дней означает максимум хранимой истории; исходный HI-Small содержит почти 18 дней.

Части 60/20/20 определяются по количеству операций в хронологическом порядке. Операции одной минуты остаются вместе. Для включённого исходного CSV ожидаются: train 2 957 790 строк, validation 985 987, test 986 286. Старое разделение по длительности периода давало test всего из 123 строк; такие результаты не используются. Только переход со старого разбиения требует запуска с prepare. Если полный расчёт с правильными размерами уже завершён, исправление очередей применяется командой `refresh_review` из начала инструкции.

| Этап в терминале | Где работает | Что получили |
|---|---|---|
| environment | GPU | Проверку работоспособности CatBoost на карте |
| prepare | CPU | Все банковские события, отдельные метки, даты и размеры трёх частей |
| features | CPU | Признаки из прошлого, найденные структуры, диагностику ограничений |
| train | CatBoost на GPU, Isolation Forest на CPU | Четыре CatBoost, выбранную модель, вторую модель и границы срабатывания |
| evaluate | CPU | Численные результаты, понятный отчёт и карточки случаев |
| workspace | CPU | Окружение карточек, формы структур, обзор периодов и сеть для просмотра |

Каждый этап сохраняет журнал в `reports/`. Ошибка останавливает дальнейшие этапы. Полный профиль требует существенно больше памяти, чем техническая проверка; ориентир для запуска: рабочая станция с 64 ГБ RAM или больше и минимум 20 ГБ свободного диска. Это запас, а не замер полного прохода. GPU не ускоряет Python-обход графа. Система не меняет драйвер или настройки ОС.

## 5. После окончания

Откройте `docs/results.md`. Сначала показаны находки в первых 100 и 500 операциях, затем сигналы при рабочем пороге, четыре модели, структурный уровень и результат прежней смешанной очереди. Теперь операции и структуры рассматриваются отдельно.

```bash
python -m streamlit run app.py
```

Откройте `http://localhost:8501`. Выберите случай, посмотрите граф и операции, рассчитайте SHAP. Решения сохраняются в `runs/demo_review`, исходные карточки не меняются. Остановка приложения: `Ctrl+C`.

## 6. Продолжение после ошибки

Не перезапускайте уже завершённые этапы без причины. Если подготовка и признаки завершились, а обучение остановилось:

```bash
python -m scripts.run_pipeline --device GPU --from-stage train
```

Если остановилась оценка, используйте `--from-stage evaluate`. Если ошибка была в построении признаков, используйте `--from-stage features`: этот этап пересчитывается целиком. Перед повтором нужно исправить причину ошибки. При внешнем пути CSV повторите `--input` с тем же путём.

Изменение признаков, поиска, окон или конфигурации требует повторного расчёта признаков и обучения. После нового обучения перезапустите Streamlit. Обучение на GPU может давать небольшие различия между повторными обучениями; один сохранённый комплект модели применяется воспроизводимо.

## 7. Чистая папка для GitHub

После успешного полного расчёта:

```bash
python -m scripts.package_release
```

Появятся `publication/hunterilka/` и `publication/Hunterilka_GitHub_v1.1.zip`. В папке находятся только разрешённые исходники, публичные документы, модели, отчёты и карточки. Полный CSV, окружение, промежуточные таблицы, личные заметки и решения пользователя не копируются. Сборка проверяет, что модели и отчёт относятся к одному полному запуску.

Создайте пустой репозиторий Hunterilka на своём GitHub без автоматически добавляемого README. Затем из рабочей папки проекта:

```bash
cd publication/hunterilka
git init
git add .
git status --short
git commit -m "Add graph AML system with reproducible GPU training"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/Hunterilka.git
git push -u origin main
```

Замените `ВАШ_ЛОГИН`. Если Git запросит имя, почту или вход, используйте собственную настройку аккаунта. Пароли и токены не добавляются в файлы проекта.

## Дополнительная сверка

`scripts.check_replay` заново проходит историю и сравнивает прогнозы с сохранённой таблицей, а также проверяет восстановление и SHAP. На полном наборе это дополнительный длительный проход; для первого запуска приложения он не нужен.
